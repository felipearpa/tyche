  - `./gradlew :pool:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.felipearpa.tyche.pool.gamblerscore.GamblerScoreItemRankPreviewTest` — 3 tests, 0 failures.

  On-device visual verification rendered the production `UsernameEditorScreen` through a temporary capture harness on the emulator (full-screen captures including the software keyboard), because the real Profile → Username walkthrough needs a signed-in session the emulator does not have. The back button and "Username" title stayed visible with the keyboard open and after scrolling in every condition: light theme at the device viewport; dark theme; and 720x1280 at density 320 (360x640 dp) with font scale 2.0 in both light and dark.

  That verification found a real defect and it was fixed: the activity keeps the platform default soft-input mode, which a Compose window resolves to panning, so on a small viewport at a large font scale the keyboard slid the whole window up and carried the top app bar off screen. `UsernameEditorScreen` now asks for `SOFT_INPUT_ADJUST_RESIZE` while it is on screen and restores the previous mode when it leaves, so no other screen's keyboard behavior changes. A second defect surfaced from the restore path: `Window.setSoftInputMode` ignores a mode of `0`, which is exactly the platform default this screen has to put back, so the mode is written through the window attributes instead. `theEditorAsksForAResizingWindowAndRestoresTheModeWhenItIsLeft` guards both halves.

  Not observed: a TalkBack listening pass. The back button's localized content description and its disabled state during saving are asserted by the instrumented tests, and the screen posts no live announcements.
